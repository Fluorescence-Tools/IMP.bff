# PRD-107: cgdye consolidation — hygiene, one LJ table, strip delegation, FRETpredict parity, physics invariants, flat `IMP.bff` API

## The assertion

`IMP.bff.cgdye` is where the *explicit* dye lives — MOL2 topology, backbone-frame
labelling, linker Metropolis sampling, rotamer libraries (the FRETpredict
libraries are module data), R0-from-spectra, κ², static/dynamic FRET regimes,
the exact kinetic master equation. It is the physics reference the AV
machinery should be checked against, and the source of rotamer ensembles for
FRET-restrained docking (PRD-108). Today none of that is *pinned*: every
FRETpredict parity test skips (no FRETpredict/MDAnalysis installed, no Hsp90
fixture), and the tree carries the hygiene debt of a move (PRD-93 stage 2).
Before cgdye can serve docking it must be consolidated: parity gated, physics
invariants asserted, duplicates merged, the strip engine shared with the AV
side (PRD-106), and a flat, self-explanatory user-facing surface at
`IMP.bff.*`.

Decisions taken with the user (2026-08-17, grilling session):

1. Docking integration is Python-only for now; a C++ `R1` position type inside
   `AVNetworkRestraint` is a gated follow-on recorded in PRD-108.
2. **Hard parity gate against FRETpredict** (Hsp90, pp11), including a
   time-boxed investigation of the existing 1.1e-3 Es gap; AV↔rotamer
   differences are recorded, not gated (PRD-108).
3. Strip: the shared `fret/strip.py` engine takes a mask; **cgdye keeps
   stripping CB** (the explicit linker is built off CA and replaces the whole
   side chain), the AV convention keeps CB — per-consumer defaults.
4. De-duplication: one CHARMM36 table and one LJ kernel; delete
   `sampling/rrt.py` (unused; `rrt_imp.py`, the tested one, becomes `rrt.py`);
   the scalar energy path routes through the vectorised one;
   `segments.py`/`fp_lib.py` untouched (fpsim copies, chisurf PRD-96).
5. Fixtures: gzip'd Hsp90/pp11 PDBs and FRETpredict `.dat` outputs under
   `test/cgdye/rotamer/data/`, JSON pins with provenance in `test/references/`.
6. API: source stays organised in `cgdye/` sub-packages; the **user-facing
   surface is flat at `IMP.bff.*`** (lazy, click-free, the whole public
   surface), **hard renames**, no aliases, names in the families `Rotamer*`,
   `Dye*`, `Linker*`, `Langevin*`, `fps_*`, `forster_radius_from_spectra`,
   `kappa2_from_dipoles`; a test asserts each export has a docstring and
   matches a family.
7. Placement: R0 and κ² live in bff (`fret`); tttrlib = photon data, chisurf =
   GUI (resolves the PRD-47 R0/κ² item on the bff side); no cross-repo code
   moves.
8. Docs: `doc/manual/structure/structure_cgdye.ipynb`, README paragraph,
   `okf/cgdye.md`. Two PRDs: this one and PRD-108 (depends on it); one commit
   per stage on `dev`; never touch `../imp`; no numba/LabelLib; cgdye → fret
   only, never the reverse.

### Stage 3 — FRETpredict parity (done 2026-08-17)
* **Investigation outcome.** A scratch env (`fretpredict-scratch`: MDAnalysis
  2.10, numpy 2.4.6 with `np.trapz = np.trapezoid`) runs the local FRETpredict
  checkout (`../dye_simulations/imp.bff/playground/FRETpredict`, e692564).
  On Hsp90 452A/637B (A594/A568 C1R cutoff30, T=293, DH) cgdye and FRETpredict
  agree to **5e-8** in Es (0.4676649 vs 0.4676650), 1e-7 in ⟨κ²⟩, Z and R0.
  The "1.1e-3 gap" was not physics: the old pins (Es 0.468768, κ² 0.970927)
  had been recorded at cgdye's default T=300 while FRETpredict's test runs at
  293. **pp11 exposed a real bug instead:** every library name resolved to the
  cutoff-30 RMF template (`templates/rotamer/<stem>.rmf3`, 33 rotamers for
  A48 C1R) because the registry filename carries `_cutoff30` and the
  resolver never substituted the requested cutoff — a `cutoff10` request
  silently scored 33 rotamers instead of 711 (Es off by 0.18, Z by 3.6).
  Fixed: `rotamer/io._library_filename` substitutes the cutoff; the
  FRETpredict DCD sets in `data/rotamer_library` (`<stem>.pdb` +
  `<stem>_cutoff<N>.dcd` + weights, read by the in-tree DCD reader) are the
  canonical libraries, the RMF templates a cutoff-30 fallback (an RMF-only
  answer for another cutoff raises). `load_protein_frames` reads multi-MODEL
  PDBs (one frame per model). After the fix pp11 (20 frames, A488/A594 C1R
  cutoff10, T=298, DH, calc + fixed R0) agrees to 1.2e-5 in E, 2.4e-5 in
  ⟨κ²⟩, 1.2e-4 in Z — the residual is PDB coordinate precision (the frames
  are exported from xtc as a multi-model PDB, 1e-3 Å).
* Fixtures `test/cgdye/rotamer/data/{openHsp90.pdb.gz, pp11_frames0-19.pdb.gz}`
  (FRETpredict test data, verbatim, gzip); pins
  `test/references/cgdye_fretpredict_pins.json` (four Hsp90 cases incl.
  swapped sites and no-DH/T300, two pp11 cases, provenance in `_note`).
  `test/cgdye/rotamer/test_fretpredict_pins.py` asserts Es/Ed1/Ed2/⟨κ²⟩/Z/R0
  to 1e-5 (Hsp90) / 2e-5, 5e-5, 2e-4 (pp11), the user-weight reweight, and
  the FRETpredict-style output files. `test_rotamer.py` pins the cutoff

### Stage 4 — physics invariants + sampler pins (done 2026-08-17)
* `test/cgdye/test_physics_invariants.py` (15 tests, < 4 s): κ² limits
  (collinear 4, perpendicular 0, parallel-⟂-r 1) and isotropic ⟨κ²⟩ = 2/3;
  R0 ∝ κ²^(1/6), R0 = 0 at κ² = 0, four R0 pins at κ² = 2/3 (A488/A594
  5.68778 nm, A594/A568 4.73766, A488/A647 5.37856, A546/A647 6.85893) and
  the FRETpredict Hsp90 R0 (5.0425682 nm at ⟨κ²⟩ 0.96926); the single-rotamer
  case where static == dynamic == dynamic+ == 1/(1+(2/3/κ²)(r/R0)^6) and the
  master equation with P = I gives the same number; static ≤ dynamic+
  (Jensen); Boltzmann weights = softmax(−E/kT), offset-invariant, no
  overflow; mean-field weights: K = 0 → prior, far protein → prior, protein
  on cluster 0 → cluster 0 loses weight; transition matrix rows sum to 1,
  symmetric counts → stationary ∝ row sums with detailed balance, absorbing
  empty rows; master equation slow-exchange (static average) and
  fast-exchange (dynamic average, dt → 0) limits, monotone in between,
  stationary vector recovered; Kronecker pair == explicit 4-state chain and
  == static regime with P = I.
* **Two physics bugs found by the invariants and fixed:**
  1. `analysis/fret.compute_exact_efficiency` solved `A G = w` instead of
     `Aᵀ G = w` (with P[i,j] = i→j the populations evolve as a row vector) —
     right only for symmetric transition matrices; the fast-exchange limit
     came out 0.878 instead of 0.764. Fixed (transposed solve); the Kronecker
     path inherits the fix.
  2. The linker Metropolis sampler (`LinkerSampler.sample`,
     `generate_rotamers`) scored **all** atom pairs — no 1-2/1-3/1-4
     exclusions ("simplification") — **and** keyed sites by atom name while
     MOL2 names are not unique across dye + linker (alexa488_r48: 83 atoms, 68
     names), so same-named atoms collapsed to one site and self-pairs at r = 0
     put ~1e31 (later ~1e6) into every frame's energy. New
     `sampling/scoring.dye_internal_system(atoms, bonds)` builds sites with
     unique ids (`dye:<serial>:<name>`) and bonds/angles/dihedrals from the
     MOL2 connectivity so `compute_exclusions` applies; alexa488_r48 geometry
     now scores 18.9 kcal/mol (was 1.66e6). Test in
     `test_rotamer_generation.py`.
* Sampler drift pins: `test/references/cgdye_sampler_pins.json`
  (`generate_rotamers(alexa488_r48, n_steps=300, write_every=10,
  cluster_threshold=1.0, seed=42)` → 30 clusters, weights now visibly
  Boltzmann-peaked, transitions, centre-coordinate hash). Note: the sampler
  is slow (2000 steps ≈ 77 s: per-atom SWIG round-trips in `apply_config`) —
  out of scope here (not speed), relevant for PRD-108's Langevin comparison.
* Cheap suite 226 passed / 0 skipped.
