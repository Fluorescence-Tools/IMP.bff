# PRD-112: one AV in `IMP.bff`

Scope is **`imp.bff` only** (owner, 2026-08-18). `imp-tricks` and ChiSurf's own
structure code are out of scope, including ChiSurf's broken `IMP.cgmol` import.

## What the migrations left

| subpackage | lines | flat-API exports |
|---|---|---|
| `cgdye` | 16 047 | 76 |
| `fret` | 5 314 | 23 |
| `quenching` | 3 009 | 36 |
| **`av`** | **1 391** | **0** |
| **`spectroscopy`** | **1 231** | **0** |
| **`restraints`** | **858** | **0** |
| **`label`** | **344** | **0** |

Three arrivals, no reconciliation: `pyext/src/av/` came from imp-tricks
(`1c3145e`, "take the rest of IMP.bff from imp-tricks") and `pyext/src/fret/av.py`
from ChiSurf (`7ab41d1`, PRD-97). **Both wrap the same C++ `IMP.bff.AV` /
`PathMap`.** Both define an `AccessibleVolume` dataclass with the *same seven
fields*. Both define `compute_av`. Only one is exported.

## The four defects

### 1. `av/compute.py` still ships the LabelLib backend

`_av_labellib`, `backend="labellib"`, and an import probe — with
`medium_test_av.py` parametrising over `["imp_bff", "labellib"]`. This
contradicts a standing decision: PRD-97 records the owner's rule of 2026-08-11,
**"no LabelLib — IMP.bff's AV is the only backend"**, and PRD-109 removed it from
QuEst along with the baseline that pinned it. `fret/av.py` refuses
`backend="labellib"` in as many words. `av/compute.py` never got the message.

This is the one item that needs no design: it is an existing decision, unapplied.

### 2. Two builders, and they are *not* redundant

The tempting move — delete one — is wrong. They take different inputs:

* `av.compute_av(atoms_xyz, atoms_vdw, source_xyz, …)` builds from **raw
  arrays**, with no PDB file and no fps document. `restraints/simple_av_network.py`
  needs exactly this.
* `fret.av.compute_av(…, pdb_path, source_info)` builds from a **PDB plus an fps
  position definition**, and *raises* without them. It carries the fps dialect,
  the strip mask, the clearance rules and PRD-105's lattice.

So the fix is **one core with two front doors**, not a deletion. Both paths
already do the same `IMP.bff.AV.do_setup_particle` + `resample()`, and each
carries fixes the other does not: the array path documents the AV-on-its-own-
particle bug and the build/resample lock split, the fps path documents the
`disc_step` trap and the source-clearance rule.

### 3. Two distance layers

`BasicAV` carries `dRmp`, `dRDA`, `dRDAE`, `pRDA`; `fret/distance.py` carries
`distance_between_mean_positions`, `average_distance`, `mean_fret_distance`,
`histogram_rda`, `av_pair_statistics`. Same quantities, two implementations, no
cross-checks between them.

### 4. Nothing here is reachable from the flat API

`av`, `spectroscopy`, `restraints` and `label` contribute **zero** of the 136
flat exports, which PRD-107 built as *the* surface. `BasicAV` and `ACV` are real
analysis objects that no documented path reaches. Separately,
`fret/kappa2.py` (dipole κ², 44 lines) and `spectroscopy/kappa2.py` (the κ²
distribution machinery, 933 lines) are two modules of the same name in one
package — not duplicates, but nobody can be expected to guess which is which.

## Stages

**Stage 0 — inventory.** The tables above, plus a written statement of which of
the two builders is canonical for each entry point. No code.

**Stage 1 — remove the LabelLib backend** from `av/compute.py`, drop the
`backend` parameter, and de-parametrise `medium_test_av.py`. Applies a standing
decision; needs no new one.
*Gate: the suite passes with LabelLib installed and with it hidden.*

**Stage 2 — one AV core, two front doors.** Extract the shared
`do_setup_particle` + `resample` + map-reading core; make both `compute_av`
entry points call it. One `AccessibleVolume` dataclass, in one place, re-exported
where the other used to live.
*Gate: byte-identical AVs before and after, on a pinned site at a pinned
resolution, through both front doors.*

**Stage 3 — one distance layer.** `BasicAV`'s four methods delegate to
`fret/distance.py`. Where the two disagree numerically, that disagreement is a
finding and gets measured before either is changed.

**Stage 4 — a public surface that matches what is there.** Export the survivors
through `api.py`, or record why a subpackage is deliberately private. Rename one
of the two `kappa2` modules.

**Stage 5 — tidy.** Delete the empty `junk/`. Re-check `distance_metrics` and the
other top-level modules for the same treatment.

## Non-goals

* **No behaviour changes to the AV itself.** Stage 2's gate is byte-identical
  output; this is a structural consolidation, not a physics change. Anything that
  moves a number stops the stage and gets measured first.
* **Nothing outside `imp.bff`.** Consumers in QuEst and ChiSurf import
  `IMP.bff.av.compute` and `IMP.bff.compute_av` today; both keep working, and
  changing them is their repositories' business.
* **`cgdye` is not restructured here.** It is 16k lines and the largest thing in
  the package, but it has a coherent surface (76 exports) and PRD-107 is recent.

## How this fails

* **Stage 2 is the risky one.** Two builders with different histories of bug
  fixes can differ in ways no test covers, and "byte-identical" is only as good
  as the sites it is checked on. If they differ, the difference is a defect in
  one of them and has to be found rather than averaged away.
* **The array front door has thinner coverage.** `medium_test_av.py` runs it in
  standalone mode; the fps door is exercised by everything. A consolidation that
  quietly regresses the array path would show up late, in `restraints`.
