# PRD-105: AV evaluation on a semi space-fixed lattice

## The assertion

Scoring a trajectory scores the *same* labelling sites against successive
structures; sampling re-evaluates slightly-moved structures. Neither case
needs the per-AV, per-evaluation full rebuild that happens today — and the
measured facts say the *reuse* the original fast-update sketch imagined
(incremental re-raster of moved atoms) **cannot pay on the screening
workload**: in the T4L trajectory **every bead moves in every frame**. What
pays instead is removing *duplication* (17 private rasters → 1 shared),
removing *arbitrary re-anchoring* (one absolute lattice), and removing
*sampling noise* from the distance block (deterministic quadrature).

This PRD records the locked v1 design (fifteen grilled decisions,
2026-08-17) and the measured evidence behind each.

## What the code does today

**Every evaluation rebuilds each AV's path map.** `AV::resample()`
(`src/AV.cpp:152`) per AV:

1. re-anchors the grid to the source **sub-voxel** — `set_path_origin(source)`
   sets origin = source − ll (`src/PathMapHeader.cpp:55-74`);
2. `sample_obstacles(linker_width * 0.5)` — rasterises **all** root leaves
   into a private cube (`src/AV.cpp:149`);
3. `fill_sphere` ×2 (block beyond linker, unblock allowed sphere);
4. `update_tiles()` + full Dijkstra (`src/PathMap.cpp:185`);
5. `sample_obstacles(radius1)` + carve;
6. `set_coordinates(get_mean_position())`.

Rasterisation is `SampledDensityMap::internal_resample` with the
BINARIZED_SPHERE kernel (`modules/em/src/SampledDensityMap.cpp:185-236`):
`reset_data()` then `data[ivox] += 1.0` per covered voxel — **integer
covering counts**, which is why add/subtract deltas on a fixed lattice are
bit-exact. Voxel boxes come from `calc_local_bounding_box`
(`modules/em/include/DensityMap.h:536`); origin quantisation is pure
`floor((loc − orig)/spacing)` arithmetic.

Distances (`av_distance`, `src/AV.cpp:46`) inverse-sample both clouds
50,000 times using a **global RNG** — scores are call-order-dependent
(the original acceptance criterion 6 is already broken by this block).

## The locked design

### Foundations

- **One absolute lattice is the exactness reference (Q2, Q5).** Voxel centres
  sit at integer multiples of `simulation_grid_resolution`, anchor (0,0,0),
  worldwide. Both the fast path and any full-recompute fallback quantise onto
  it, so fast == full is bit-identical *by construction*. Consequences
  accepted: shipped numbers move within grid-discretization noise vs today
  (measured in the migration table); scores are no longer
  translation-invariant (grid-noise scale); rerun order-independence becomes
  provable (the lattice is stateless — no run-history phase).
- **Lattice anchoring is the default (Q3).** Pinned test references
  (`test_AccessibleVolume.py` mean position, `test_AVNetworkRestraint.py`
  score) regenerate once to lattice values.
- **Legacy opt-out kept one transition period (Q4).** `space_fixed=False`
  reproduces today's sub-voxel source anchoring byte-for-byte; deprecated on
  arrival; removed by a later PRD after the reference shift is measured on
  real fps.json sets and consumers (fpsimp PRD-96, PRD-99 calibration)
  migrate.

### Mechanics

- **Windows: minimal, linker-defined, rolling (Q6 = B, Q13).** The linker
  length defines the grid, per the code's own rule (`PathMapHeader`: edge =
  2·ll). Each AV's window is the cube of edge 2·(ll + reach padding), centre
  = lattice-quantised source; it rolls — relocated by whole voxels only —
  whenever the quantised source moves ≥ 1 voxel (roll-to-centre). PBC/torus
  indexing of the window array makes a roll an O(1) index remap; wrap-around
  phantoms are provably invisible because a phantom entering the far face is
  ≈ 2·ll from the source, inside `fill_sphere`'s blocked-beyond-linker
  region. Decided on the A/B: T4L sources walk ~3 voxels/frame, so rolls
  fire ~every frame under *both* policies — permanent padding (A) buys
  nothing; minimal windows win.
- **One shared occupancy raster (Q7).** Occupancy is f(atoms, lattice,
  extra_radius) — independent of ll, which only masks. So the system keeps
  one raster per (spacing, extra-radius) **class** — 4 classes on T4L, not 17
  AVs × 2 passes — sized to the union of windows ∪ atom reach, grown on
  demand. Windows *read* it (extract-where-present, fill-zero-beyond);
  reading is value-identical to rasterising the window directly
  (integer counts per lattice point). Rolls under the shared map are pure
  window moves — zero re-raster ever. Saves ~14.7 → ~2 ms/frame on T4L.
- **Search unchanged in v1 (Q8).** `update_tiles` + cold Dijkstra per AV per
  frame, exactly as today. It becomes the dominant term (~10.8 ms/frame) —
  warm-start/LPA* relabelling is the *entire* v2, deliberately deferred
  because it is the bit-exactness-critical component and its win on
  all-beads-move workloads is unproven.
- **Deterministic distances: lattice quadrature, K=100 (Q9, Q10).** Each
  cloud is coarsened on the lattice to ≤ K = 100 weighted representative
  points (block centroids preserve the mean exactly); pair distance = the
  exact weighted K×K double sum. Measured: MC-class accuracy (0.16 Å max vs
  0.12 Å for 50k MC), deterministic, ~25–50× faster in C++ (numpy A/B was
  implementation-unfair; a C++ A/B against MC is *required* before sign-off).
  Moments closed form rejected on data (2.2 Å systematic bias). Exact FFT
  cross-correlation is the test-only oracle (~300 ms runtime, unusable).
  The distance block lives in **this** PRD with its own design,
  independent of PRD-94's Gaussian moments; the MC RNG order-dependence
  defect is fixed by replacement, not patched.

## Two-tier exactness contract

- **Tier 1 — bit-exact.** Occupancy, maps, mean position: any space-fixed
  mode's fast path equals its full recompute bit-for-bit;
  `shared_map=True` equals `shared_map=False` bit-for-bit on the lattice;
  `space_fixed=False` equals today's code byte-for-byte.
- **Tier 2 — deterministic-accurate.** Pair distances: same number every
  call, call-order-independent, error budget stated and measured against the
  FFT oracle (K-curve), with K tunable.

## Requirements

1. **Lattice anchoring** — quantised window/grid origins on the global
   lattice under `space_fixed`; the full-recompute fallback quantises with
   the same rule (one shared lattice); `space_fixed=False` preserves today's
   anchoring byte-for-byte and emits a deprecation warning.
2. **Rolling windows** — minimal linker-defined windows, integer-voxel
   rolls, PBC/torus indexing, roll diagnostics. Private-raster modes
   maintain occupancy by subtract/add deltas plus slab work on roll;
   shared-map modes roll for free.
3. **Shared occupancy map** — per (spacing, extra) class; extent = union of
   windows ∪ atom reach, grow-on-demand; constructed only when
   `space_fixed`; windows read it.
4. **Quadrature distances** — `distance="quad"`, `quad_k` (default 100);
   coarsen per cloud once per frame; deterministic; `distance="mc"` keeps
   today's path.
5. **Diagnostics** — per run: skip / local / full counts per AV, roll
   counts, moved-bead counts, quad-K and error estimates; exposed via SWIG.
6. **Tests + build** — parameterized 6-mode suite (below) in `test/`;
   C++ A/B of MC vs quad timed in the real evaluation path; everything built
   and run in the `arm64` env via the imp-local-build workflow.

## Consumers

- **Trajectory screening** — `plot_AVScreening.py`, `imp_engine.screen()`:
  measured target ~38.5 → ~16 ms/frame (~2.4×) on T4L: raster 14.7 → ~2,
  distances 14.5 → ~0.6, search 10.8 unchanged.
- **Sampling / refinement** — `mean_position_restraint=False` scoring,
  `dock_minimize` cycles: repeated identical evaluations hit the no-change
  skip (near-zero cost per repeat); proof is count-based (skip fires), not
  a speed-up percentage.
- **fpsimp (PRD-96), calibration (PRD-99)** — consumers of the regenerated
  reference numbers during the transition window.

## Out of scope

- **Warm-start / incremental Dijkstra (LPA*)** — v2 in its entirety.
- **Moments-based distances** — PRD-94 designs the Gaussian; this PRD's
  distance design is quadrature and stays independent of it.
- **Exact FFT distances at runtime** — oracle for tests only.
- **Sparse / blocked data structures** (idea 5) — the dense shared grid is
  ~18–20k vox on T4L; revisit for large complexes.
- **Fixing the MC RNG order-dependence inside MC** — replaced by quad;
  documented as xfail in mc modes.

## Accepted costs and risks

- Reference numbers move at grid-noise + quad-error scale — measured
  migration table, one-time regeneration, legacy opt-out bridges.
- Translation variance at grid noise (absolute lattice).
- MC modes retain the RNG order-dependence defect (xfail-marked).
- ~2.4× honest on T4L (search floor 10.8 ms stands until v2); uncapped win
  on sampling repeats.

## Acceptance criteria

1. **Lattice exactness (tier 1).** In every `space_fixed` mode, a forced
   full recompute and the normal evaluation path produce bit-identical
   density and mean position. Test: same frame, both paths, exact equality.
2. **Legacy byte-identity.** `space_fixed=False, distance="mc"` reproduces
   today's pinned references exactly (the current `test_AccessibleVolume.py`
   / `test_AVNetworkRestraint.py` values, unchanged).
3. **Shared == private.** On the lattice, `shared_map=True` and `False`
   yield identical maps and scores, bit-for-bit.
4. **Mode matrix green.** The parameterized suite passes in all 6 modes;
   order-independence passes in quad modes and is xfail-marked in mc modes.
5. **Quad accuracy and speed (in C++).** Error vs FFT oracle at K=100 within
   the stated budget (target ≤ MC 50k's 0.12 Å class); C++ timing A/B of the
   real evaluation path recorded (MC vs quad).
6. **Determinism.** Interleaved evaluation orders give identical scores in
   quad modes.
7. **Diagnostics.** Skip/local/full, rolls, moved-bead counts reported for
   every run and asserted non-trivial in the benchmarks.
8. **Recorded tables** (no speed gate): T4L before/after wall time
   (baseline 38.5 ms/frame), per-mode; reference-number shift table vs
   legacy; sampling repeat-evaluation benchmark showing the skip fires
   (counts).
9. **One merge, staged commits** as specified; references regenerated once.

### Where the implementation deviates from the locked text, and why

* **Torus/PBC indexing → in-place shift.** A roll keeps the retained block by
  copying it into the new window array and rasterises only the exposed slabs
  (up to three boxes) at the coordinates the retained block was rasterised
  at, so the whole window again equals one full raster and the ordinary
  moved-atom delta applies. Same work bound as a phase remap (no re-raster
  of retained voxels), but every consumer of the map (tiles, Dijkstra edges,
  `get_xyz_density`, `IMP.em.write_map`) keeps plain row-major indexing;
  a torus phase would have had to be understood by all of them. In shared-map
  mode a roll is a window read anyway.
* **Window edge** = `2·floor(ll/h + ½) + 1` voxels, centre = lattice-quantised
  source (`round(s/h)`); every voxel centre within `ll` of the source lies
  inside (|s/h − q| ≤ ½). T4L @2 Å: 23³ (legacy 22³); T4L @0.5 Å: 81³
  (legacy 80³). "Reach padding" is not needed for the window: the AV
  cannot extend past `ll` and obstacles are read from the raster.
* **Shared extent** = union of requested windows ∪ atom reach, plus a
  3-voxel margin, grow-only. On T4L the four class rasters are 130–200k
  voxels (the windows reach ±23 Å beyond the sources), not the ~20k
  atom-only estimate — irrelevant to cost, which is per atom footprint.
  With every bead moving, a delta would cost two spheres per atom, so
  `update()` falls back to one full raster when ≥ half the atoms moved
  (bit-identical either way).
* **Quadrature carries second moments.** Block centroids alone gave a max
  error of 0.24–0.27 Å at K = 100 on the T4L screening set (2.0 Å grid) —
  MC-50k class, but above the 0.16 Å the numpy prototype reported. Adding
  each block's second central moments and correcting every pair term to
  second order (`E f(|D+ξ|) ≈ f(d) + ½[f''(d)·q + f'(d)(tr C − q)/d]`,
  `C = C₁+C₂`, `q = DᵀCD/d²`) drops the max error to **< 0.005 Å** at K = 100
  (K-curve on the 1.5 Å pair 132–55: 10: 0.0024, 30: 0.0002, 100: 0.0001,
  300 → 0.0000 Å; efficiency error at K = 100: 3·10⁻⁵). The mean position is
  still preserved exactly; the estimator is still a deterministic weighted
  double sum over ≤ K lattice blocks. K = 100 stays the default.
* **Two latent legacy defects fixed in both paths.** `PathMap::update_tiles`
  called `edge_computed.resize(false, nvox)` (arguments swapped): the flags
  were resized to zero and `get_edges` read the previous frame's freed,
  still-set bits — after the first evaluation edges were never recomputed,
  so a moved structure kept the old connectivity (this is what made
  scores evaluation-order dependent beyond MC noise, and it is why the
  "38.5 ms" baseline was cheaper than a correct legacy run). And
  `AV::resample` carved tiles with `density *= 0` and never restored them,
  so repeated resamples of a moving structure shrank the AV frame after
  frame (`score_last = inf` on the T4L benchmark). Legacy mode keeps the
  anchoring and algorithms byte-for-byte for a *single* evaluation (pins:
  maps at 0.5/1.5 Å × 3 sites × 2 clearances, mean positions, MP distances)
  and is now history-independent; the second-evaluation and 5-frame legacy
  pins in `prd105_legacy_pins.json` are from the fixed code, because the old
  code's repeated evaluations had no reproducible value.
* **Constant-factor cleanups in the search, bit-identical:** neighbour
  offsets passed by const reference (were copied per tile), Dijkstra's
  frontier comparator specialised away from a `std::function` heuristic
  call; the AV cloud is computed once per result and shared by the mean
  position and the quadrature. Search is otherwise untouched (Q8).
* `space_fixed=False, shared_map=True` raises `ValueException` at
  construction (Q11); `set_space_fixed(False)` warns once per process.

### Algorithm alternatives tried and rejected (2026-08-17)

Asked "why not a distance transform / a better algorithm for where the dye
can go", two experiments were built, measured and reverted (tree left at
`97cca77`):

* **Hybrid Euclidean/geodesic search** — tiles the source sees along a
  straight voxel path get their exact Euclidean distance (a straight linker is
  a valid path and none is shorter); only the visibility frontier is seeded
  into the Dijkstra, which labels the shadow. With face-step (DDA) parents the
  visibility is too conservative (large false shadow, seeds ≈ shadow ≈ most
  tiles) and the frame got *slower* (0.86 → 1.22 ms); with 26-neighbour
  Bresenham parents the chain cuts corners between blocked face neighbours
  and tunnels — AVs +37 % voxels, model distances +0.67 Å mean, max 12 Å —
  and it was still slower (1.10 → 1.36 ms). Exact per-tile line traversal
  would cost about what the search costs. Not pursued further.
* **Distance transform for the obstacles** (one additively-weighted field
  `min_i(|x−c_i|−r_i)` serving every inflation radius and the carve): saves
  ~3/4 of the class-raster CPU (0.25 → 0.08 ms CPU/frame) and one window
  read per AV — ~0.03 ms wall — and breaks the subtract/add delta path for
  local moves (a min-field must be re-minned over the change box). Not
  worth it at this point; a geodesic distance transform (fast marching)
  costs per pop what the 26-stencil relaxation costs and only changes the
  metric.

Where the frame is (0.7 ms): 17 bounded 26-neighbour searches at ~90 µs
each (~55 %), per-AV O(window) passes (~25 %), rasters, pair sums, pool.
Grid spacing is the remaining lever (2.5 Å: 0.51 ms; 3.0 Å: 0.39 ms), and it
is a user parameter.

### `search_mode="euclidean"` (2026-08-17)

Added on request as a *model* option: the linker is straight — a tile is
reached iff the source point sees its centre along a segment free of
(inflated) obstacles, traversed exactly voxel by voxel (Amanatides–Woo DDA),
and lies within the linker length; its cost is the Euclidean distance; no
path search. Tiles in the protein's shadow are dropped. On T4L @2 Å the
Euclidean AVs have ~40 % of the path-search voxels (7.7k vs 19.4k per
frame), 18 of 1980 pair evaluations become empty, model distances differ by
5.6 Å rms from the path search — a much more restrictive dye model. And it is
**not faster**: exact per-tile visibility costs about what the bounded
search costs (0.82 vs 0.77 ms/frame). Two O(1) approximations of visibility
were tried first (Bresenham parent chains, with and without a face-step
fallback): one is far too conservative, the other leaks around corners
(neither matched exact segment visibility on more than ~80 % of tiles), so
the exact traversal is what ships. Default stays `"dijkstra"`.

### Correction: the "26-neighbour" stencil was 18 (2026-08-17, same day)

`PathMapHeader::set_neighbor_radius(sqrt(3.0))` with the offset test
`d² <= r²` in double excludes `d² = 3` (`sqrt(3.0)² = 2.9999999999999996`),
so the "symmetric 26" stencil that shipped in pass 3 had **18** offsets
(faces + edges, no corners). That is what produced the "AVs 15–25 % smaller,
means up to 2.5 Å away, 1.1 Å rms" numbers and the 388 → 185 ms search
halving: an 18-stencil overestimates body-diagonal paths by 40 % (1+√2 vs
√3), not a tunnelling fix. Found by the `search_mode="euclidean"` cross-check
(Dijkstra costs 28 % above the straight distance on visibly free lines).
Fixed by `sqrt(3.0) + 1e-6`; a test now asserts 26 (and 30) offsets.

The honest 26-vs-30 comparison on T4L @2 Å: AVs 3 % smaller (23.3k vs 24.0k
voxels per frame), model distances **0.42 Å rms, max 3.0 Å**, mean +0.08 —
the tunnelling fix proper, at grid-noise scale. Mean position of the
0.5 Å test AV moves 0.0004 Å. Lattice pins regenerated once more
(`chi2_C2_33p` 13.5051 at K=50, 13.5082 at K=100). Speed with the real 26
stencil is back to about the pass-2/3 level: ~1.0 ms/frame quiet, i.e. the
"below 1 ms" of pass 3 was partly the metric bug — see the timing note in
pass 5 below.

### Pass 5 — memory safety (2026-08-17)

* `PathMap::set_path_map_header` did not reset the voxel-location arrays: a
  shape change left arrays of the old size marked as computed, and the
  in-place `set_origin_fast` then wrote the new voxel count into them. Now
  the arrays are rebuilt on shape change and sized-checked (`loc_size_`).
* The 1-in-4 aborts of the full test suite ("Fatal Python error: Aborted"
  during garbage collection, malloc checksum botch) traced to the **pip
  LabelLib** backend of `av/compute.py`: under Guard Malloc it dies with
  EXC_BAD_ACCESS inside `Grid3DExt::excludeConcentricSpheres` — an
  out-of-bounds read that, with the normal allocator, corrupts the heap for
  the rest of the process. The AV lattice suite is clean under Guard Malloc
  and malloc heap-checking. `medium_test_av.py` no longer exercises the
  LabelLib backend by default (`IMP_BFF_TEST_LABELLIB=1` opts in); 0/8
  crashes afterwards vs 1/4–1/8 before.

### SIMD (2026-08-17)

Asked "simd?": NEON was put where the data is contiguous. (1) Interior-tile
relaxation of the 26 stencil in row form — 9 rows of 3 consecutive tiles,
one 4-lane load each (lane 3 masked with an infinite edge length), vector
add/compare, horizontal any-lane test, scalar path only for the rare
