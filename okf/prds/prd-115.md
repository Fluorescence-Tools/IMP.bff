# PRD-115: a differentiable lattice — adjoint of the field solver, per-voxel features, and a learned field on `MlpCore.h`

**Status: stage 0 done 2026-08-19 (T-20260819-02); stages 1-3 open.** The
tttrlib half is done and committed (T-20260819-01: `933a4cc7a` core +
examples, `8ac9b0a52` whole-model `MlpModel` + JSON, `cd0cdb000` perf parity
on thread-CPU time against the pre-refactor code): `MlpCore.h`, vendored
verbatim at `include/internal/MlpCore.h`, guarded by
`test/test_vendored_mlpcore.py`, which also compiles a bff-only program and
evaluates/differentiates a tttrlib-trained model to 1e-12. Board ticket for
stage 0: **T-20260819-02**.

## 0. Why, and why this is not PRD-110

PRD-110 wanted a network as a *PDE solver* (collocation PINN, parametric in
θ) to make calibration cheap; it stopped because θ was not identifiable from
one decay. PRD-111 then found the two things this PRD is built on:

1. **The model is over-parameterised in the wrong place.** `slow_factor^n(contact_distance)`
   builds the same mobility field for many (`slow_factor`, `contact_distance`)
   pairs (log D correlation 0.927, equilibrium overlap 98.7 %). No number of
   sites separates them. PRD-111 §4: *re-parameterise on the quantity the data
   determine — the field.* A field parametrised by a small smooth function of
   per-voxel features (distance to surface, local crowding, nearest quencher
   type) **is** that re-parameterisation; the network is just the smooth
   function, with a handful of weights and physics doing the rest.
2. **Every gradient in the stack is a finite difference through the solver**
   (`benchmark/quenching_identifiability.py:235`), 2N forwards per Jacobian,
   with the θ-independent-time-step rule (`:178-188`) as the only thing standing
   between it and a 2× error. A joint six-site fit is affordable today only
   because θ has five entries; a field with hundreds of degrees of freedom
   (or a network with a few hundred weights) is not fittable by finite
   differences at all.

So: the physics stays exactly where it is (the lattice, the explicit scheme,
`exp(-k dt)`, the shell rule); the *unknown parts* of the physics become
learnable; and the solver gets an adjoint so their gradient costs one extra
sweep, not 2N. This is a universal differential equation, and it is what the
tttrlib port was for. PRD-111's non-goal *"no surrogate, no network"* stands
for the surrogate half: **nothing here replaces the solver.**

## 2. What bff has to build

Nothing below needs a new dependency. Everything is `std::vector<double>`,
flat `ng³` row-major, the conventions of `DiffusionSolver.h`.

### A. `diffusion_propagate_adjoint` — the whole mechanical task (stage 0, **done**)

Landed as designed below — and, per the one-codebase rule, the kernel itself
lives in **tttrlib** (`modules/math/include/LatticeDiffusion.h`, header-only,
std-only, its own dot-product test there) and is vendored verbatim at
`include/internal/LatticeDiffusion.h`; `src/DiffusionSolver.cpp` is now a thin
IMP-facing wrapper, and `test/test_vendored_headers.py` keeps both copies
(`MlpCore.h`, `LatticeDiffusion.h`) identical. What differed from the sketch: the reverse sweep is
a *gather* (each output voxel owned by one iteration, so it parallelises like
the forward and needs no atomics), templated on the flux form; the
Python-facing overload returns `[dL/dd | dL/ddecay | dL/dcur]` in one
`out_view` array (three `ng³` out-parameters would be walked by SWIG at
~340 ns each); and `GridDiffusionSolver.gradient(dL_dF, n_steps, n_out,
density)` chains through `dt/dg²`, `-dt·e^{-k dt}` and the `p b/Σ(p b)`
normalisation `run()` applies, returning `GridDiffusionGradient(d_diffusion,
d_rate, d_density)` in physical units.

`sweep()` (`src/DiffusionSolver.cpp:28-66`) is linear in `cur` at fixed
`d`, `decay`: `nxt = A(d, decay, bounds) · cur`. The reverse pass is `Aᵀ`
applied to the adjoint density `p̄`, plus accumulation of `∂L/∂d` and
`∂L/∂decay` from `(p̄, cur)` at each step:

- Smoluchowski flux `0.5(d0+d_m)(p0−cur_m)·bounds_m` is symmetric in the
  interface coefficient → `Aᵀ` is the same stencil up to the `bounds` mask
  and the trailing `·decay[c]` (which multiplies rows in the forward and
  columns in the reverse). Itô is *not* self-adjoint; write both, test both.
- `∂L/∂decay[c] += p̄_next[c]·(p0 − Σflux)`; `∂L/∂d` gets the six
  neighbour terms of the flux, per form.
- observable `F(t_k) = Σ p` → seed `p̄ = ∂L/∂F(t_k)` on every interior voxel
  at the reported steps (the `n_out` machinery already marks them).
- **checkpointing, not storage**: 4 800 × 41³ × 8 B ≈ 2.6 GB. Store every
  `n_out`-th state (already produced), re-forward the segment on the way back
  (√n-style, ~2× forward cost, ~`ng³·n_steps/n_out·8` bytes).
- unfold the coefficients: today `d = D·dt/dg²` and `decay = exp(−k dt)` are
  folded in Python (`sampling/smoluchowski.py:307-309`). Either return
  `∂L/∂d`, `∂L/∂decay` and let Python chain through `dt/dg²` and
  `−dt·exp(−k dt)`, or add a variant taking `D`, `k`, `dt`, `dg`. Do the
  first (no signature change, one line of numpy each), keep the second as a
  convenience if it earns its place.
- honour the θ-independent time-step rule: the adjoint differentiates the
  *discrete* scheme, so it is exact for the scheme actually run; the rule is
  what makes the scheme's answer mean the same thing across θ.

Signature sketch (`include/DiffusionSolver.h`):
```cpp
// dL/dd, dL/ddecay, dL/dcur0 for L = Σ_k dL_dF[k] · F(t_k), F from diffusion_propagate
// with the same (cur, d, decay, bounds, ng, flux_form, n_steps, n_out).
void diffusion_propagate_adjoint(
    const std::vector<double>& cur, const std::vector<double>& d,
    const std::vector<double>& decay, const std::vector<double>& bounds,
    int ng, int flux_form, int n_steps, int n_out,
    const std::vector<double>& dL_dF,            // length n_steps/n_out + 1
    std::vector<double>& dL_dd, std::vector<double>& dL_ddecay,
    std::vector<double>& dL_dcur0);
```
Bindings: `IN_ARRAY1` for `dL_dF`, `ARGOUTVIEWM_ARRAY1` for the three outputs
(the out-parameter caveat in `okf/log.md`: never hand an `ng³` vector back
through a SWIG wrapper).

**Validator (the gate):** the dot-product identity against the *forward*
solver, `⟨p̄, (∂F/∂d)·v⟩ == ⟨(∂F/∂d)ᵀ p̄, v⟩` with `(∂F/∂d)·v` from a
central difference of `diffusion_propagate` along a random `v` — 1e-8
relative or better on the PRD-111 A124 site at `ng = 41`, both flux forms —
plus agreement with `benchmark/quenching_identifiability.py::jacobian()` on
its five θ (chain rule through the map builders in numpy). Stage 0 stops if
the identity does not hold.

### B. Per-voxel features (stage 1)

A kernel `voxel_features(...)` returning `(n_active, n_features)` row-major
plus the `n_active` index list into `ng³` (the AV is ~1 % of the cube: 1 158
of 41³ voxels in PRD-111 stage 1). θ-independent, computed once per site:

- one atom loop away from `slow_near_atoms` / `quenching_map`
  (`src/QuenchingMap.cpp:30-36, 62-69`): distance to nearest atom overall and
  **per type code** (the `kQ`/`rC` per-atom vectors of
  `maps.atomic_quenching_parameters` carry the typing), contacting-atom count
  at 2–3 radii, radial distance from the anchor;
- ready-made non-local features reachable today only through the AV object
  layer: `AVOccupancyMap::read_window_counts` (integer crowding),
  `PathMap::get_tile_values(PM_TILE_PATH_LENGTH / COST)`;
- later: SAS depth per voxel, surface normal / curvature (nothing exists).

Layout is the MLP's input matrix directly; standardise with the JSON scaler.

### C. Learned field assembly (stage 2)

`FieldModel` (Python first, C++ when it becomes a restraint): features →
`mlpcore::forward` → `D(r)`, `k(r)` (or a multiplicative correction to the
physical `k(r)`), positivity by construction (`softplus` output or `exp`) →
`diffusion_propagate` unchanged. Gradient: `diffusion_propagate_adjoint` →
`∂L/∂D`, `∂L/∂k` → `mlpcore::backward(features, dL_dy) → dparams`. Fit with
scipy L-BFGS on the flat vector, likelihood from tttrlib. First target: the
PRD-111 stage-0 degeneracy — replace `(slow_factor, contact_distance)` by a
one-hidden-layer function of (nearest-atom distance, crowding); show it fits
the six-site data at χ² ≈ 1 with **fewer** effective parameters and a
well-conditioned Fisher on the field's principal components.

### D. Drift term / potential of mean force (stage 3, optional)

The solver has no drift: `p_eq` is uniform (Smoluchowski). A learned
`U(r)` (PRD-114's `W(r)` is the same object) needs a drift flux
`J = −D(∇p + p∇U/kT)`, discretised with the interface weights that keep
`p_eq ∝ exp(−U/kT)` exact (Scharfetter–Gummel / exponential fitting), its
adjoint, and `∇U` from `MlpCore`'s order-1 pass. Same file, same test.
Also the force for `BrownianWalk`/`quenched_donor_photons` (particle path)
so field and particle samplers stay comparable (`particle_vs_field_diffusion.md`).

### E. Rotational dynamics (separate PRD)

There is no orientational degree of freedom anywhere in bff (PRD-111
non-goal). An orienting potential needs a new kernel — diffusion on S² with
the same `d`/`decay`/`bounds` folded-coefficient contract so the adjoint
machinery from A carries over. Not in scope here; named so nobody thinks
`MlpCore.h` covers it.

## 3. Constraints and hygiene

- No torch/jax at runtime (`IMP.bff` ships in IMP via conda-forge, PRD-110 §5).
  `MlpCore.h` header-only/std-only is the whole reason it was vendored.
- `include/internal/MlpCore.h` is read-only here; changes go to `../tttrlib`
  and are re-copied (`test/test_vendored_mlpcore.py`).
- The two solver invariants stand: outer shell written to zero; rate as
  `exp(−k dt)`, never `1 − k dt`.
- `#pragma omp` is inert in this build (`okf/validation/openmp_is_not_enabled.md`);
  no threading arguments.
- All PRD-111 data are synthetic from the model being fitted; a learned field
  validated only against `GridDiffusionSolver` output inherits that. The
  first *real* test is a measured multi-site decay set — the same gate
  PRD-111 left open.
- Found by the survey and fixed (2026-08-19): `benchmark/quenching_identifiability.py`
  imported `IMP.bff.quenching.solver`, which PRD-113 moved to
  `IMP.bff.sampling.smoluchowski`; both quenching benchmarks were un-runnable.

## 3b. What the tttrlib side guarantees (so stage 2 can rely on it)

- **Numerics**: `MlpCore.h`'s forward equals `NeuralNet::train`'s to the bit
  (same GEMM order in the tttrlib build; the portable GEMM in the copy agrees
  to 1e-13 — `test_mlp_core.cpp`), and every gradient path is validated two
  independent ways (dot-product identity vs the forward-mode Dual pass;
  central differences), including through the scalers.
- **Cost**: order-0 forward+backward for a 1000-point batch through a
  2-16-16-1 net is ~1 ms in C++ (5 ms from Python via the argout bindings);
  order-2 forward+backward for 5000 points through 2-20×8-1 is ~100 ms. A
  learned `D(r)`/`k(r)` over ~10³ reachable voxels is therefore negligible
  next to one lattice solve (1–10 s) — the field is static in `t`, evaluate it
  once per θ, never inside the sweep.
- **Format**: `tttrlib.neural_net` v1 JSON, read by `mlpcore::model_from_json`
  with any nlohmann-compatible object (bff's `internal/json.h` 3.6.1 works).
- **Namespace**: `TTTRLIB_MLPCORE_NAMESPACE` may be defined to
  `IMP::bff::internal` before the include (the contract test does).
