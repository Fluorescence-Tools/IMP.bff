# PRD-106: strip mech — one selection-driven mechanism to strip side chains (and whole residues / atom masks) from the obstacle set

## The assertion

A labelling position's fps.json entry can say *which atoms must not be an
obstacle*: the `strip_mask` field (`pyext/src/fret/fps_schema.py:163`),
authored in the shipped examples for exactly this —

```
"strip_mask": "(resid 119 and not name CA CB C N O) or resname HOH SOL WAT DU CL NA 'Cl-' 'Na+'"
```

— the side chain of the labelled residue, plus solvent and ions. Today that
field is **read by no code**: the AV build ignores it and instead clears the
source with an inflated `allowed_sphere_radius` (`fret/av.py:124-132`), and the
side-chain stripping that *is* implemented lives in two unrelated places with
two different keep-sets and no shared engine. A single strip **mech(anism)** —
one grammar, one engine, two outputs (stripped hierarchy, filtered obstacle
array) — makes `strip_mask` real, gives the AV build the FPS-convention clearing
it already aims at, and replaces the duplicated strippers.

## What the code does today

Four fragments, no shared semantics:

1. **`strip_mask` is declared, authored, and unused.** The schema field
   ("Selection mask of atoms removed as obstacles before the AV simulation",
   `fps_schema.py:163-167`) is populated in the shipped files — T4L and
   TG2/flex author a *grammar* (`chain <id> and resid <n> and not name ...`,
   `or`, parentheses, quoted `'Cl-'`) — but a repo-wide read finds zero
   consumers. Everything downstream of `read_fps_json` reaches the AV build via
   `source_info` dicts that never carry it.
2. **The AV build substitutes clearance for stripping.** `fret/av.py:124-132`
   says it out loud: FPS/LabelLib got source clearance "by stripping the
   attachment residue's atoms instead"; imp.bff inflates
   `allowed_sphere_radius = max(1.5, 0.5*linker_width + 0.5*disc_step)` and
   treats the source as "an obstacle to itself" (`av/compute.py:266-268`). The
   obstacle set is then every atom in the input array (`av/compute.py:265-289`).
3. **A whole-residue stripper exists but is dead.** `_strip_residue_atoms`
   (`fret/av.py:557-612`) removes a residue's atoms from a `(N,4)` obstacle
   array by PDB-record matching with a coordinate-distance fallback. It is
   defined, never called, and strips the *whole* residue — not the side chain.
4. **cgdye has a working one-site stripper with a hard-coded keep-set.**
   `strip_sidechain_at_site` (`cgdye/labeling/attachment.py:73-94`) removes
   everything except `("N","CA","C","O","OXT")` at a single (chain, resnum),
   mutating the hierarchy in place; wired into `attach_dyes(strip_site_sidechain=True)`
   and covered by the hGBP1 tests. Note this keep-set **strips CB**, while the
   authored AV masks keep CB (`not name CA CB C N O`) — the two consumers
   disagree on what "backbone" means, which is exactly the kind of choice a
   shared mechanism must expose rather than bury.

Cross-repo proof the strip is needed at the seam: chimol's labelling workaround
(`T-20260815-01`, progress update 5) hand-builds a per-site PDB with the
attachment residue removed (`_stripped_pdb_for`) because imp.bff's obstacle
path would otherwise let the residue block the AV.

## The mechanism

A single engine, living in `fret` (the lower layer — `cgdye` already imports
`fret`, never the reverse), with one specification language and two outputs:

**The language — a PyMOL-shaped subset, fixed to what the examples author.**

```
mask    ::= expr
expr    ::= term ( "or" term )*            # union
term    ::= factor ( "and" factor )*       # intersection
factor  ::= "not" atomset | "(" expr ")" | atomset
atomset ::= "chain" id                     # one-letter chain id
          | "resid" num                    # residue sequence number
          | "resname" name+                # residue names (HOH, SOL, WAT, ...)
          | "name" name+                   # atom names (CA, CB, C, N, O, ...)
          | "elem" sym+                    # element symbols (optional now, harmless later)
```

Semantics: **the selected atoms are removed** (the "mask" is the atom set).
Three intents, all expressible with the grammar, each matching an existing
fragment:

- **strip a side chain** — `chain A and resid 119 and not name <backbone>`.
  The backbone keep-set is *part of the mask*, not a constant: the AV
  convention keeps `CA CB C N O`, cgdye labelling keeps `N CA C O OXT`.
  A convenience shorthand (`nothing but backbone at that residue`) may be added
  once the grammar lives, but is not required: the mask must be able to say it.
- **strip a whole residue** — `chain A and resid 119`, or `resname HOH` for
  solvent/ions (the water case is why whole-residue stripping belongs in the
  same engine, not in a separate function).
- **strip an arbitrary atom set (flexible tags)** — any `name`/`elem` mask.

**The engine, one apply with two outputs.** `apply_strip_mask(mask, structure,
out_kind)` where `out_kind` is `"hierarchy"` (a stripped copy of the hierarchy)
or `"obstacles"` (a filtered `(M,4)` coordinates+vdw array for the AV build).
The application is **non-destructive**: the source hierarchy/PDB is never
mutated; consumers that do want in-place mutation get a thin convenience wrapper
around the copy. The old cgdye default keep-set becomes the callable's default,
unrolling to a mask — no second keep-set constant in the codebase.

**Reject loudly.** A mask that selects nothing (typo'd `chain`, `resid` past the
last residue, a `name` present nowhere) raises and names the mask, matching the
fps.json schema's no-silent-no-op philosophy.

## Requirements

1. **`fret/strip.py` — the engine.** Parse the grammar above and apply it to an
   IMP hierarchy: predicates `chain`/`resid`/`resname`/`name` with `not`, `and`,
   `or`, parentheses; two outputs (`stripped hierarchy`, `(M,4)` obstacle
   array); non-destructive by construction.
2. **`strip_mask` becomes live in the AV build.** `fret/av.py` /
   `av/compute.py` read the position's `strip_mask` and build the obstacle set
   from the stripped structure. `allowed_sphere_radius` keeps its real role
   (source-clearance margin); it stops being a *substitute* for stripping — a
   position that declares a strip and one that pre-computes the same removal by
   hand must give identical AVs.
3. **cgdye converges.** `strip_sidechain_at_site` keeps its observable
   behaviour (default keep-set, return count of removed atoms, existing tests
   green) but delegates to the engine; `attach_dyes(strip_site_sidechain=True)`
   unrolls to the grammar default. The `("N","CA","C","O","OXT")` constant
   exists in exactly one place (as the callable's default).
4. **Dead code and duplication removed.** `_strip_residue_atoms`
   (`fret/av.py:557`) is deleted or re-expressed on the engine; no keep-set
   logic survives outside the engine.
5. **Selection diagnostics.** A strip report — mask string, selected atom
   count, per-position — available to callers and to the fps.json editor, so a
   screening/display run can audit which atoms were actually removed
   (deliberately mirroring PRD-105's "how much changed" diagnostic in spirit).
6. **The language is pinned by fixture, not by prose** — every authored mask in
   the shipped T4L and TG2/flex fps.json files is a test case.

## Consumers

- **AV build** — `fret/av.py` `compute_av`, `av/compute.py` obstacle assembly.
  The T4L/TG2 files already declare the strips; today they are ignored and the
  side chains/waters stay as obstacles, which must not be the shipped behaviour.
- **cgdye labelling** — `strip_sidechain_at_site`, `attach_dyes(...,
  strip_site_sidechain=True)`, and the scripts/cli/examples that call them
  (`cgdye/cli.py:171`, the hGBP1 scripts, `label_protein.py`,
  `examples/structure/hgbp1_label_and_sample.py`).
- **fps.json-driven screening/display** — a position whose strip is honoured
  now matches what the file author intended when they wrote `strip_mask`.
- **chimol seam (cross-repo)** — `T-20260815-01`'s `_stripped_pdb_for`
  currently re-derives a stripped structure by hand; a public
  stripped-hierarchy output gives it one code path to consume instead. imp.bff
  owns the interface; chimol's internals are not this PRD's scope.

## Out of scope

- **The AV algorithm itself** — resample, Dijkstra, grid/anchor questions
  (PRD-105 and its ideas section), Gaussian moments (PRD-94), calibration
  (PRD-99). This PRD only changes *which atoms feed the obstacle set*.
- **A full PyMOL grammar.** Only the subset the examples author (plus the
  `elem` option, kept cheap now, disambiguated later if the grammar grows).
  No ranges (`1-10`), no wildcards beyond what `name`/`resname` allow, no
  neighbourhood/surround operators.
- **Retiring `allowed_sphere_radius`.** Positions without a strip keep today's
  clearance path bit-identical; the PRD removes the *substitution*, not the
  field.
- **The cgdye in-place API.** `strip_sidechain_at_site` stays available; only
  its implementation moves.
- **chimol internals** — the consumer side of the seam is theirs to land
  (already underway under T-20260815-01).

## Acceptance criteria

1. **The authored masks apply.** For every position in the shipped T4L and TG2
   `flex.fps.json`, applying its `strip_mask` to the loaded structure removes
   exactly the atoms a hand-written per-atom mask removes (fixture records
   per-position selected-atom lists). This pins the grammar to real usage.
2. **Side-chain strip is the headline case.** `chain A and resid R and not name
   CA CB C N O` on a labelling site yields an obstacle set whose removed atoms
   are precisely the non-backbone atoms of `R` (recorded per-atom/name), and a
   stripped hierarchy that keeps `N CA C O` for the cgdye default spelling —
   the two keep-set conventions from §„What the code does today“ are both
   test-pinned, and their difference is data, not a buried constant.
3. **AV parity for strip positions.** A T4L position with its mask honoured
   produces a density bit-identical to building the AV from a pre-stripped copy
   of the same structure (the FPS convention), and non-empty with the default
   `allowed_sphere_radius` — the case that today can only be reached by the
   chimol hand-strip. Positions *without* a strip produce bit-identical results
   to today.
4. **cgdye unchanged at the call surface.** `test_attachment.py::test_strip_sidechain_at_site`
   and the hGBP1 481 medium test pass with `strip_sidechain_at_site` delegating;
   the removed-atom count and keep-set are identical to today.
5. **Dead code gone, single implementation.** `_strip_residue_atoms` no longer
   exists (or is a one-line re-export); a grep for a second backbone keep-set
   constant finds nothing outside the engine/callable default.
6. **Non-destructive by test.** Applying a strip (either output) leaves the
   source hierarchy's atom list and coordinates untouched — asserted, since the
   old cgdye path mutated and the migration must not silently keep mutating.
7. **Loud invalid masks.** A mask selecting zero atoms, or referencing a missing
   `chain`/`resid`/`name`, raises with the mask string in the message; no
   silent no-op (tested for at least one typo class per predicate).
