# PRD-106: strip mech — one selection-driven mechanism to strip side chains (and whole residues / atom masks) from the obstacle set

**Status:** done (2026-08-27)
**Done:** All six requirements, and six of the seven acceptance criteria as written -- the seventh's substance by a different rule (below). The mask is a full selection expression (#IMP::bff::SelectionExpression), in either spelling, compiled to an #IMP::atom::Selection; all 43 shipped `strip_mask` values parse and apply, each checked against **its own** structure and atom by atom (1); both keep-set conventions stay data (2); a masked volume's density is **bit-identical** to one built from a pre-stripped structure (3); the cgprobe call surface is unchanged (4); there is one implementation and no second keep-set constant (5); stripping is non-destructive (6). The decorator path honours the field at last -- `AV::set_av_parameter` reads it -- `strip_report` says what a mask did, and an fps.json may state a document-level `strip_mask` that is a **union** with each position's own. Tests: `test/selection/test_selection_expression.py` (35), `test/label/test_strip_acceptance.py` (62), `test/label/test_strip.py` (7), `test/label/test_av_strip.py` (18), and the mask/sharing interaction in `test/test_av_lattice.py` (3). Suite: 1208 passed, 3 xfailed, 30 subtests; 37 in the expensive sweeps.
**Missing:** Nothing open. **Acceptance 7 is not met as written and will not be**: it asks that a mask selecting zero atoms *raise*. It does not, deliberately -- `test_a_mask_never_silently_selects_nothing` settled that earlier, and the shipped data proves it right, because TG2 position A52 is an **alanine** whose only side-chain atom is CB, which the mask keeps: a legitimately empty strip. What the criterion was defending against is met another way: a mask that cannot be *read* is refused loudly, and one that reads and selects nothing is visible through `strip_report` rather than silent.
**Next:** Nothing -- closed. Asked four times whether it really was done, and each time the check found something a passing suite or a stale document was hiding: a fixture vacuous for 23 of 43 cases (every mask run against T4L, including TG2's); a parity test comparing point *counts* where acceptance 3 says bit-identical; a missing `strip_obstacles`, requirement 1's second output, lost in the C++ port, and a second copy of the backbone keep-set (requirement 3); then `strip_obstacles` still dropping rows after a strip had become a radius of zero everywhere else; and on the last pass, only stale prose -- this document and its index entry still describing the defect in the present tense under a "done" status. All fixed.

**Consequences recorded rather than open:** a masked volume cannot join a shared occupancy raster (a shared grid *is* one obstacle set, and each position strips its own residue), so the flagship fps.json no longer shares; and honouring the masks moved the T4L quadrature score from 22.699 to 22.593, which is the number the file was always asking for.


## The assertion

A labelling position's fps.json entry can say *which atoms must not be an
obstacle*: the `strip_mask` field, authored in the shipped examples for
exactly this —

```
"strip_mask": "(resid 119 and not name CA CB C N O) or resname HOH SOL WAT DU CL NA 'Cl-' 'Na+'"
```

— the side chain of the labelled residue, plus solvent and ions.

When this was written the field was **read by no code**: the AV build ignored
it and cleared the source with an inflated `allowed_sphere_radius` instead,
and the side-chain stripping that *was* implemented lived in two unrelated
places with two different keep-sets and no shared engine. A single strip
**mech(anism)** — one language, one engine, two outputs — makes `strip_mask`
real, gives the AV build the FPS-convention clearing it already aims at, and
replaces the duplicated strippers.

**It is real now** (2026-08-27). Every shipped mask parses and applies, the
volumes are computed against the structure the file describes, and the T4L
quadrature score moved from 22.69935116408601 to 22.593263882270314 in
consequence — the number the file had always been asking for. The sections
below are the design as it was specified; **The mechanism** is what was built,
and the implementation record says where the two differ and why.

## What the code did before this (2026-08-17)

Four fragments, no shared semantics:

1. **`strip_mask` is declared, authored, and unused.** The schema field
   ("Selection mask of atoms removed as obstacles before the AV simulation",
   `fps_schema.py:163-167`) is populated in the shipped files — T4L and
   TG2/flex author a *grammar* (`chain <id> and resid <n> and not name ...`,
   `or`, parentheses, quoted `'Cl-'`) — but a repo-wide read finds zero
   consumers. Everything downstream of `read_fps_json` reaches the AV build via
   `source_info` dicts that never carry it.
2. **The AV build substitutes clearance for stripping.** `fret/av.py:124-132`
   says it out loud: FPS/LabelLib got source clearance "by stripping the
   attachment residue's atoms instead"; imp.bff inflates
   `allowed_sphere_radius = max(1.5, 0.5*linker_width + 0.5*disc_step)` and
   treats the source as "an obstacle to itself" (`av/compute.py:266-268`). The
   obstacle set is then every atom in the input array (`av/compute.py:265-289`).
3. **A whole-residue stripper exists but is dead.** `_strip_residue_atoms`
   (`fret/av.py:557-612`) removes a residue's atoms from a `(N,4)` obstacle
   array by PDB-record matching with a coordinate-distance fallback. It is
   defined, never called, and strips the *whole* residue — not the side chain.
4. **cgdye has a working one-site stripper with a hard-coded keep-set.**
   `strip_sidechain_at_site` (`cgdye/labeling/attachment.py:73-94`) removes
   everything except `("N","CA","C","O","OXT")` at a single (chain, resnum),
   mutating the hierarchy in place; wired into `attach_dyes(strip_site_sidechain=True)`
   and covered by the hGBP1 tests. Note this keep-set **strips CB**, while the
   authored AV masks keep CB (`not name CA CB C N O`) — the two consumers
   disagree on what "backbone" means, which is exactly the kind of choice a
   shared mechanism must expose rather than bury.

Cross-repo proof the strip is needed at the seam: chimol's labelling workaround
(`T-20260815-01`, progress update 5) hand-builds a per-site PDB with the
attachment residue removed (`_stripped_pdb_for`) because imp.bff's obstacle
path would otherwise let the residue block the AV.

## The mechanism

One engine, one language, two outputs, and one rule for what "removed" means.

**The language is #IMP::bff::SelectionExpression** -- `SelectionExpression.h`
/`.cpp`: a tokenizer, a precedence parser, an evaluator over a flat atom table
and a compiler to #IMP::atom::Selection. It is the full language rather than
the subset this PRD first specified, because the files in this stack are
authored in two spellings and both had to be read:

| | one spelling | the other |
|---|---|---|
| residue number | `resi 5`, `i. 5` | `resid 5` |
| residue name | `resn ALA`, `r. ALA` | `resname ALA` |
| a list | `name CA+CB` | `name CA CB` |
| a range | `resi 50-60` | `resid 50 to 60` |
| segment | `segi`, `segid` | `segname` |
| file serial | `id` | `serial` |
| whole residues | `byres SEL` | `same residue as SEL` |
| water | `solvent` | `water` |
| near something | `SEL within 5 of SEL2` | `within 5 of SEL2` |

Both are accepted, including mixed -- every shipped T4L mask *is* mixed. Which
spelling an expression is in is **detected**, because the two disagree about
one thing: whether `index` counts from 0 or from 1. A caller may declare it
instead. `within`/`beyond`/`around` are answered against coordinates; `pbc` is
refused rather than ignored, there being no cell here to wrap in.

Compiling to #IMP::atom::Selection is the point: what comes out composes with
everything that takes one. `chain` becomes `set_chain_ids`, `resi` a
`set_residue_indexes`, `resn` a `set_residue_types`, `name` a `set_atom_types`,
`elem` a `set_element`. Four kinds of term have no IMP predicate -- a wildcard,
the fields IMP's hierarchy does not carry (`segi`, `alt`, `id`), `index`, and
the whole-structure operators -- and enter the algebra as a Selection over
exactly the particles they matched.

**A strip is a radius of zero** (maintainer, 2026-08-27). A rasteriser asks
`distance < radius`, so an atom of no size blocks nothing; there is no need to
build each volume a particle list of its own. Keeping every atom in the list
means every volume indexes the same particles whatever it strips -- which is
what the incremental window machinery needs -- and nothing is mutated on a
model that another thread is reading, which matters because volumes resample in
parallel. The radii live in a per-map override vector.

That needed one rule in each rasteriser, because both inflate every radius by
the probe radius before testing it: **a non-positive radius is not inflated and
not sampled**. Without it a stripped atom still carves a probe-sized hole.

**Two outputs**, both stripping that way: a stripped hierarchy
(`strip_hierarchy`, which really does remove -- it edits a structure rather
than computing a volume) and the `(M, 4)` obstacle array (`strip_obstacles`),
which keeps every row and zeroes the radius of what the mask names, so the
array stays row-for-atom with the structure it came from.

**Two masks, a union.** An fps.json may state a `strip_mask` at the document
level -- what the *structure* carries that no volume should be blocked by --
beside the per-position one, which is about the labelling site. The readers
fold them together so a position taken alone is self-contained (schema 1.1,
additive).

**Reject loudly** -- but only what cannot be *read*. A mask that reads and
selects nothing is not an error: TG2 position A52 is an alanine whose only
side-chain atom is CB, which the mask keeps, so it legitimately strips nothing.
`strip_report` makes that visible rather than silent. See acceptance 7 below,
which asked for the opposite and is the one criterion deliberately not met.

## Requirements

*All six met. The engine is C++ (`SelectionExpression.h`, `StripMask.h`,
`ProbeAttachment.h`) rather than `fret/strip.py`: this module's Python surface
was retired by PRD-117 while this PRD was open.*

1. **The engine.** Parse the language and apply it to an IMP hierarchy:
   predicates `chain`/`resid`/`resname`/`name` with `not`, `and`, `or`,
   parentheses; two outputs (`strip_hierarchy`, `strip_obstacles`);
   non-destructive by construction. *(Delivered wider than asked: the full
   language, both spellings, compiled to #IMP::atom::Selection.)*
2. **`strip_mask` becomes live in the AV build.** Both doors read the
   position's `strip_mask` and build the obstacle set from the stripped
   structure -- the PDB path through `stripped_pdb_for`, the decorator path
   through `AV::set_av_parameter` and a radius of zero. `allowed_sphere_radius` keeps its real role
   (source-clearance margin); it stops being a *substitute* for stripping — a
   position that declares a strip and one that pre-computes the same removal by
   hand must give identical AVs.
3. **cgprobe converges.** `strip_sidechain_at_site` keeps its observable
   behaviour (default keep-set, return count of removed atoms, existing tests
   green) but delegates to the engine; `attach_dyes(strip_site_sidechain=True)`
   unrolls to the grammar default. The `("N","CA","C","O","OXT")` constant
   exists in exactly one place (as the callable's default).
4. **Dead code and duplication removed.** `_strip_residue_atoms` is gone, and
   there is one backbone list (`protein_backbone_atom_names`), shared by the
   language's `backbone` keyword and the labelling site's keep-set. The AV
   default is deliberately a different set -- it keeps CB and drops OXT -- and
   a test pins that the difference is data.
5. **Selection diagnostics.** `strip_report` — the mask, the selected atom
   count, the atoms and the residues they belong to — so a screening or display
   run can audit what was actually removed, and an empty strip is visible
   rather than silent.
6. **The language is pinned by fixture, not by prose** — all 43 authored masks
   in the shipped T4L and TG2/flex fps.json files are test cases, each checked
   against **its own** structure and atom by atom. An empty result has to be a
   checked claim (the residue has no atom outside the keep set), because
   `set() == set()` passes while testing nothing.

## Consumers

*Where each landed. The Python names below were retired by PRD-117 while this
PRD was open; these are the surfaces that consume the mechanism now.*

- **AV build** — both doors. `compute_av` takes obstacles as an `(M, 4)` array
  whose zeroed rows are transparent; `av_from_position` /
  `compute_av_from_structure` read the position's mask on the PDB path; and
  `AV::set_av_parameter` reads it on the decorator path, which is what
  `probe_network_restraint_set`, the docking engine and the lattice suite go
  through. The T4L and TG2 files declared strips that were ignored; they are
  not ignored now, and the T4L quadrature score moved accordingly.
- **cgprobe labelling** — `strip_sidechain_at_site` and
  `attach_probes(..., strip_site_sidechain=True)`, and the programs and
  examples that call them (`bin/imp_bff`, the hGBP1 scripts,
  `examples/structure/hgbp1_label_and_sample.py`). These *edit* a structure
  rather than compute a volume, so they strip by removing atoms
  (`strip_hierarchy`), not by zeroing a radius.
- **fps.json-driven screening and display** — a position whose strip is
  honoured matches what the file's author meant, and `strip_report` says which
  atoms went.
- **chimol seam (cross-repo)** — a public stripped-hierarchy output exists for
  it to consume (`strip_hierarchy`, `strip_obstacles`, `selection_atoms`).
  imp.bff owns the interface; chimol's internals are not this PRD's scope.

## Out of scope

- **The AV algorithm itself** — resample, Dijkstra, grid/anchor questions
  (PRD-105 and its ideas section), Gaussian moments (PRD-94), calibration
  (PRD-99). This PRD only changes *which atoms feed the obstacle set*.
- **A full PyMOL grammar.** Only the subset the examples author (plus the
  `elem` option, kept cheap now, disambiguated later if the grammar grows).
  No ranges (`1-10`), no wildcards beyond what `name`/`resname` allow, no
  neighbourhood/surround operators.
- **Retiring `allowed_sphere_radius`.** Positions without a strip keep today's
  clearance path bit-identical; the PRD removes the *substitution*, not the
  field.
- **The cgdye in-place API.** `strip_sidechain_at_site` stays available; only
  its implementation moves.
- **chimol internals** — the consumer side of the seam is theirs to land
  (already underway under T-20260815-01).

## Acceptance criteria

*Met unless marked. Criterion 7 is deliberately not met -- see the
header and **The mechanism**.*

1. **The authored masks apply.** For every position in the shipped T4L and TG2
   `flex.fps.json`, applying its `strip_mask` to the loaded structure removes
   exactly the atoms a hand-written per-atom mask removes (fixture records
   per-position selected-atom lists). This pins the grammar to real usage.
2. **Side-chain strip is the headline case.** `chain A and resid R and not name
   CA CB C N O` on a labelling site yields an obstacle set whose removed atoms
   are precisely the non-backbone atoms of `R` (recorded per-atom/name), and a
   stripped hierarchy that keeps `N CA C O` for the cgdye default spelling —
   the two keep-set conventions from §„What the code does today“ are both
   test-pinned, and their difference is data, not a buried constant.
3. **AV parity for strip positions.** A T4L position with its mask honoured
   produces a density bit-identical to building the AV from a pre-stripped copy
   of the same structure (the FPS convention), and non-empty with the default
   `allowed_sphere_radius` — the case that today can only be reached by the
   chimol hand-strip. Positions *without* a strip produce bit-identical results
   to today.
4. **cgdye unchanged at the call surface.** `test_attachment.py::test_strip_sidechain_at_site`
   and the hGBP1 481 medium test pass with `strip_sidechain_at_site` delegating;
   the removed-atom count and keep-set are identical to today.
5. **Dead code gone, single implementation.** `_strip_residue_atoms` no longer
   exists (or is a one-line re-export); a grep for a second backbone keep-set
   constant finds nothing outside the engine/callable default.
6. **Non-destructive by test.** Applying a strip (either output) leaves the
   source hierarchy's atom list and coordinates untouched — asserted, since the
   old cgdye path mutated and the migration must not silently keep mutating.
7. ⛔ **Loud invalid masks.** A mask selecting zero atoms, or referencing a
   missing `chain`/`resid`/`name`, raises with the mask string in the message;
   no silent no-op (tested for at least one typo class per predicate).

   **Not met, deliberately.** A mask that cannot be *read* raises and names
   the token. A mask that reads and selects nothing does not, because that is
   a legitimate answer: TG2 position A52 is an alanine whose only side-chain
   atom is CB, which the mask keeps. `strip_report` makes an empty strip
   visible instead, and `test_a_mask_never_silently_selects_nothing` had
   already settled the question before this PRD was re-opened.

* 2026-08-27 (later) — **a strip is a radius of zero, not a shorter list**
  (maintainer). The first cut handed each volume its own filtered particle
  list; giving the stripped atoms no size is simpler and safer. It needed the
  rule "a non-positive radius is not inflated and not sampled" in both
  rasterisers -- `PathMap::sample_obstacles` and `AVOccupancyMap` -- because
  both add the probe radius to every radius before testing it, so a zeroed
  atom would otherwise still carve a probe-sized hole.

  Three pieces of delta bookkeeping came with it, each silent-wrong if missed:
  `full_raster` records a transparent atom's `last_` entry anyway, so a later
  frame has a truthful "before" to subtract; `apply_local` subtracts only what
  was added; and the moved-set classification does *not* skip a transparent
  atom, because `r != last[3]` is what catches one that has just become
  transparent. `strip_obstacles` zeroes rather than drops, so the array stays
  row-for-atom with its structure, and a test proves the equivalence through
  the public API: a volume built from zeroed rows is bit-identical to one
  built from the shorter array those rows were dropped from.

  Caught by the tests on the way: the first version set the override on the
  `PathMap` only, and the default path is `space_fixed`, which rasterises
  through `AVOccupancyMap` -- so the mask silently stopped reaching the
  obstacle set until the private maps carried it too.
