# PRD-108: rotamer ensembles for FRET docking — R1 positions, the AV↔rotamer table, Langevin/Brownian dye samplers

Depends on [PRD-107](prd-107.md). Decisions (user, 2026-08-17 grilling):

1. **Docking integration is Python-only now.** A C++ `R1` position type
   inside `AVNetworkRestraint` (point cloud in the site frame, clash
   re-weighting via the PRD-105 occupancy map) is a follow-on gated by the
   AV↔rotamer table (stage 2).
2. **`simulation_type = "R1"`** = FRETpredict-style 1:1: the full library
   transformed into the site frame and screened against the protein, per
   rotamer **centre + dipole + weight** kept (all atoms retained), so the pair
   matrix R_ij, κ²_ij, w_i·w_j → FRET rate distribution and E_static/E_dyn are
   available downstream. R2/R3 reserved (R2 = sampled library, R3 = mixture).
   C++ warns on unknown types; `fps_positions_for_docking()` filters.
3. Object: **`RotamerEnsemble(fret.av.AccessibleVolume)`** — `points` (N,4) =
   centre + weight so every AV helper works unchanged; pair/rate kernel and κ²
   live in `IMP.bff.fret`.
4. AV↔rotamer differences are **recorded** (table authoritative), pins guard
   drift; not a gate.
5. Samplers: real Langevin, `integrator="md"|"bd"`; the collision walk stays
   `sample-dof-walk`; thermodynamic pins (equilibrium populations vs
   Boltzmann `generate_linker_rotamers`, md ⇄ bd, oscillator temperature,
   free-particle MSD).

## Stages

### Stage 0 — `RotamerEnsemble` + pair kernel in `fret` (done 2026-08-17)
* `fret/distance.py`: `fret_pair_geometry(points1, w1, points2, w2, mu1=None,
  mu2=None)` → R_ij, κ²_ij (2/3 without dipoles), normalised w_i·w_j, ⟨κ²⟩;
  `fret_pair_efficiencies(geometry, forster_radius_A, tau0=None)` → static /
  dynamic1 / dynamic2, per-pair E, rate ratio, k_fret; `fret_pair_distribution`
  = both. `test/fret/test_pair_distribution.py`.
* `cgdye/rotamer/ensemble.py`: `RotamerEnsemble(AccessibleVolume)`
  (`points` = centre + weight; `mu`, `atoms`, `atom_names`, `resnames`,
  `energies`, `partition`, `library`, `chain`, `residue`;
  `params.simulation_type = "R1"`), `RotamerEnsemble.from_site(structure, chain,
  residue, library, *, temperature, electrostatic, potential, ignore_h,
  sigma_scaling, epsilon_scaling, frame_index, position_name)`,
  `.pair_geometry / .pair_distribution / .fret_efficiencies(other,
  forster_radius | donor+acceptor)`, `rotamer_ensembles_from_fps(fps_json,
  structure, library_map)`; module helpers `resolve_backbone_site`,
  `backbone_rotation`, `transform_library_to_site`, `selector_atom_indices`.
  `RotamerFRET._frame_fret` is now built on two ensembles + the fret kernel —
  the FRETpredict pins (stage 3 of PRD-107) pass unchanged (5e-8).
  `test/cgdye/rotamer/test_rotamer_ensemble.py`: AV helpers accept it, Hsp90
  numbers equal FRETpredict's and RotamerFRET's, full 37×7 matrix, isotropic
  κ² against a plain AV, positions from fps.json. Exports:
  `IMP.bff.RotamerEnsemble`, `rotamer_ensembles_from_fps`, `SIMULATION_TYPE_R1`,
  `fret_pair_*`.
