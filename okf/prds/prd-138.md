# PRD-138: flat consolidation, and the interface pass that follows it

**Status**: active (2026-09-07). **Done**: the merge table, one commit each
(Faspr, PathMap, Quenching, Fcs, internal/Cif, FPS, Linker, Pto, Labelizer,
Rotamer, ProbeLibrary, ProbeSampling, FRET, States/AVModel), suite 1780/0
after every one; `utility/merge_sources.py`. Five rows narrowed, each
annotated in the table. **Missing**: the interface pass. **Next**: the
interface pass, starting with the `compute_`/`build_`/`find_` → `get_`/
`create_` naming, then the 19 raw-pointer returns.

## Why

The owner: the project has too many individual `.cpp` files to track, the
interfaces should be made right while it is pre-release, and the layout must
stay **flat** because that is what IMP's module tooling globs
(`include/*.h`, `src/*.cpp`). So: no subsystem directories; merge the files
that are split by implementation detail rather than by concept.

The census behind the table (2026-09-07): 97 public headers, 106 sources,
40 SWIG topic files. Naming is already IMP-style (`get_` 925, `set_` 231);
19 raw-pointer returns; 180 `double**` numpy.i out-params (the idiom, not a
problem) against `std::vector` copies across the boundary (the problem).

## Rules

1. One merge, one commit, suite unchanged. The commit message lists the
   source files, because `git blame` on a merged file points at the merge.
2. Merged files carry a `// ---- from X.cpp ----` section marker per source,
   so the history is findable by eye as well as by `git log -S`.
3. The unity build (`bff_all.cpp`) already compiles every source into one
   TU, so a name collision between two sources is impossible by construction;
   the tool does not need to reason about it.
4. Each merge's SWIG topic file follows the header: one `.i` per merged header.

## The interface pass (after the merges)

- ~50 `compute_`/`build_`/`find_` free functions → IMP's `get_`/`create_`.
- 19 raw-pointer returns → value, or a ref-counted pointer, each audited.
- `std::vector<double>` returns that copy across the boundary → numpy.i views.
- Data/config handling lands with the pip packaging step of PRD-137.
