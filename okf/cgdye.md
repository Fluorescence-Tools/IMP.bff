# cgdye — the explicit-dye layer of imp.bff

**What it is.** `IMP.bff.cgdye` models a fluorescent label as an atomistic dye
+ linker: labelling a residue in its backbone frame (`attach_dyes`,
`resolve_dye_site`, side chain stripped through the shared strip engine
`fret/strip.py`), dye topology from MOL2 (`parse_dye_mol2`,
`build_dye_topology`, one CHARMM36 LJ table `topology/dye.py`), rotamer
libraries (FRETpredict's, module data `data/rotamer_library`: `<stem>.pdb` +
`<stem>_cutoff<N>.dcd` + weights — the cutoff in a library name is honoured),
FRETpredict-compatible rotamer FRET (`RotamerFRET`: screened libraries,
E_static/E_dyn1/E_dyn2, ⟨κ²⟩, Z; parity pinned to FRETpredict), linker
sampling (`LinkerSampler`, `generate_linker_rotamers`, torsion/rigid-body
RRT), Boltzmann / mean-field / kinetic weights, the exact kinetic master
equation (`fret_efficiency_exact_kinetic`), density analysis, MD/MC runner
(`sim/runner.py`), mmCIF/RMF/DCD/NMR I/O and a `dye` command line.

**Where the physics lives.** R0 from spectra (`fret/forster.py`) and κ² from
dipoles (`fret/kappa2.py`) are in `IMP.bff.fret` — properties of the label
pair, not of a coordinate model. cgdye imports `fret`, never the reverse.
tttrlib = photon data, chisurf = GUI (PRD-47 R0/κ² item resolved on the bff
side, 2026-08-17). `spectroscopy/kappa2.py` (κ² *distributions*, chisurf
origin) is a separate toolkit; folding it into `fret/kappa2.py` is a PRD-47
follow-up.

**How to use it.** Flat: `IMP.bff.<Name>` (mapping and naming rule in
`pyext/src/api.py`, installed by `pyext/swig.i-in`; the sub-packages
`cgdye/{labeling,topology,sampling,rotamer,io,analysis,sim,scripts}` are the
source organisation). `import IMP.bff` does not import cgdye; nothing in the
library needs `click` (`cgdye/utils.import_click` stubs it; click is a CLI
dependency declared in `conda-recipe/meta.yaml`). Manual page:
`doc/manual/structure/structure_cgdye.ipynb`; example:
`examples/structure/hgbp1_label_and_sample.py`.

**Conventions.**
* Labelling keep-set `SITE_KEEP_ATOM_NAMES = ("N","CA","C","O","OXT")` —
  cgdye **strips CB** (the linker is built off CA and replaces the side chain);
  the AV convention keeps CB. Each consumer owns its default, the engine takes
  the mask (PRD-106).
* Names say what they are (`Rotamer*`, `Dye*`, `Linker*`, `fret_*`, `fps_*`,
  `forster_*`, `kappa2_*`, `strip_*`, ...); retired names are gone, no aliases
  (`test/test_public_api_names.py`).
* Tests: `test/cgdye` (cheap `test_*`, `medium_test_*`, `expensive_test_*`),
  `test/fret`, `test/test_public_api_names.py`. Physics pins:
  `test/references/cgdye_fretpredict_pins.json` (FRETpredict reference values
  with provenance), `cgdye_sampler_pins.json`; fixtures
  `test/cgdye/rotamer/data/`. `test/cgdye/test_physics_invariants.py`.
* Build: `pyext/src/Files.cmake` and `test/Files.cmake` are regenerated by the
  IMP configure step (`__init__.py` excluded); new/renamed Python files need a
  reconfigure to be symlinked into the build tree.
